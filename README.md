# رشدى لنجارة الموبيليا

كتالوج أثاث عربي باتجاه RTL، مبني باستخدام React وTypeScript وVite. يتضمن صفحات رئيسية ومنتجات وتفاصيل المنتج ومن نحن والتواصل، مع البحث والتصفية وروابط واتساب. بيانات المنتجات محلية حاليًا، ويمكن استبدال الخدمة لاحقًا بواجهة API.

## متطلبات التشغيل

- Node.js بإصدار LTS حديث (يتضمن npm).
- PowerShell أو Terminal داخل مجلد المشروع.

```powershell
npm install
npm run dev
```

افتح عنوان Vite الذي يظهر في نافذة الأوامر، غالبًا `http://localhost:5173`.

إذا ظهر أن `npm` غير معروف على Windows، ثبّت Node.js من [الموقع الرسمي](https://nodejs.org/) ثم أغلق PowerShell وVS Code وافتحهما من جديد. إذا كان Node.js مثبتًا في `C:\Program Files\nodejs` لكن PATH غير مضبوط، يمكن تشغيل الأوامر مؤقتًا هكذا:

```powershell
$env:Path = "C:\Program Files\nodejs;$env:Path"
npm.cmd install
npm.cmd run dev
```

## إعداد بيانات الورشة

حدّث القيم مرة واحدة في `src/config/siteConfig.ts`:

- اسم الورشة ووصف الموقع.
- `WHATSAPP_NUMBER`: الرقم الدولي بالأرقام فقط، من دون `+` أو مسافات، مثل `2010XXXXXXXX`.
- رقم الهاتف والعنوان ومواعيد العمل.
- روابط فيسبوك وإنستغرام وخرائط Google.
- صورة الواجهة الرئيسية وصور التصنيفات.

لا يفتح زر واتساب محادثةً برقم غير مضبوط؛ تظهر رسالة إرشادية حتى يُضاف الرقم الصحيح.

حدّث `https://your-domain.example` في `public/robots.txt` و`public/sitemap.xml` إلى نطاق الموقع الفعلي قبل النشر. النطاق الحالي مجرد قيمة توضيحية.

## إدارة المنتجات والصور

يمكن إضافة المنتجات الجديدة من لوحة الإدارة على المسار `/admin` من دون تعديل ملفات الكود. المنتجات القديمة ما زالت في `src/data/products.ts`، أما المنتجات الجديدة التي تضيفها من اللوحة فتُحفظ في Supabase وتظهر تلقائيًا في الموقع.

### إعداد Supabase مرة واحدة

1. أنشئ مشروعًا في Supabase، ثم افتح **SQL Editor** وشغّل محتوى `supabase/catalog.sql`.
2. من **Authentication > Users** أنشئ حسابًا للمالك، ثم انسخ UUID الخاص به.
3. في SQL Editor شغّل أمر `insert` الموجود في آخر ملف SQL بعد استبدال النص `PASTE-AUTH-USER-UUID-HERE` بالـ UUID. هذا يضيف الحساب إلى قائمة المديرين المسموح لهم.
4. انسخ `.env.example` إلى `.env.local` وضع **Project URL** و**anon/public key** من إعدادات المشروع في القيم المقابلة، ثم أعد تشغيل `npm run dev`.
5. افتح `/admin` وسجّل الدخول. اكتب اسم المنتج وسعره، وارفع صورة أو أكثر، ويمكنك إضافة بقية التفاصيل ثم النشر.

المفتاح العام فقط مطلوب في واجهة الموقع. لا تضع `service_role` key في ملفات الواجهة أو متغيرات `VITE_`. صلاحيات القراءة والكتابة محمية بسياسات RLS في قاعدة البيانات والتخزين. الخطة المجانية مناسبة كبداية ضمن حدودها التي يحددها Supabase، وقد تحتاج ترقية إذا زاد الاستخدام أو التخزين.

المنتجات الجديدة تظهر مع بيانات الكتالوج المحلية. تعديل/حذف المنتجات المحلية القديمة ما زال يتم من `src/data/products.ts`؛ لوحة الإدارة حاليًا مخصصة للمنتجات التي أُنشئت فيها.

صور الواجهة والتصنيفات موجودة في `src/config/siteConfig.ts`. عند تعطل صورة منتج، يعرض الموقع صورة بديلة محلية من `public/furniture-placeholder.svg`.

## التحقق والبناء والنشر

```powershell
npm run lint
npm test
npm run build
npm run preview
```

تعمل اختبارات الوحدات باستخدام `npm test`. ويتحقق سير GitHub Actions من lint والاختبارات والبناء عند فتح طلب دمج إلى `main` أو `master`.

### النشر المجاني على GitHub Pages

يوجد سير عمل GitHub Actions في `.github/workflows/deploy.yml` يبني الموقع وينشره تلقائيًا عند الدفع إلى فرع `main` أو `master`. لبدء النشر:

1. ارفع المشروع إلى مستودع GitHub.
2. من إعدادات المستودع افتح **Settings > Pages**، ثم اختر **GitHub Actions** في **Build and deployment > Source**.
3. إذا أعددت Supabase، أضف `VITE_SUPABASE_URL` و`VITE_SUPABASE_ANON_KEY` إلى **Settings > Secrets and variables > Actions > Variables**. المفتاح هنا هو المفتاح العام فقط، وليس `service_role`.
4. ادفع التغييرات إلى `main` أو `master`، أو شغّل سير العمل يدويًا من تبويب **Actions**.
5. بعد نجاح سير العمل، افتح رابط الموقع الظاهر في **Settings > Pages**.

رابط هذا المشروع على GitHub Pages: https://mohamedroshdy404.github.io/Carpentryworkshop-/

يضبط البناء مسار الملفات تلقائيًا لمستودع المشروع، ويجهز صفحة بديلة حتى تعمل روابط الصفحات الداخلية عند فتحها مباشرة. في النشر على استضافة ثابتة أخرى، ارفع محتويات `dist` واضبط إعادة توجيه المسارات غير الموجودة إلى `index.html`.

حدّث النطاق في ملفات SEO قبل إرسال خريطة الموقع لمحركات البحث.

## نقاط التنفيذ

- إنشاء نص واتساب ورابط `wa.me` في `src/utils/whatsapp.ts`، ويُقرأ الرقم من `src/config/siteConfig.ts`. يفتح واتساب برسالة مجهّزة للمراجعة والإرسال من العميل.
- خدمة بيانات المنتجات والبحث حسب الاسم والفئة والوصف والخامات والألوان والكلمات المفتاحية في `src/services/productService.ts`.
- عنوان الصفحة والوصف وCanonical وبيانات Schema.org للمنتج تُدار حسب المسار في `src/App.tsx` و`src/utils/seo.ts`.
